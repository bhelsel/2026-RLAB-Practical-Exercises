Learning Objectives

By the end of this workshop, you should be able to:

  • Explain the difference between [, [[, and $, and know when to use each
  • Subset a data frame by rows and columns using data[rows, columns]
  • Explain the difference between simplifying and preserving subsetting
  • Build logical conditions with ==, >=, <, &, |, and ! to select rows
  • Combine multiple conditions (including with parentheses) to answer a realistic research question
  • Translate a plain-English data request into R subsetting code

The core question to ask yourself throughout: what information do I want, and where is it stored?

Activity 1: [, [[, and $

Why three operators?

R gives you three tools for pulling things out of an object, and they are not interchangeable:

Operator What it returns Typical use
[ A subset of the same type/structure (can hold 0, 1, or many elements) “Give me a smaller version of this object”
[[ A single element, unwrapped from its container “Give me the contents of this one slot”
$ A single named element (shorthand for [[ with a name) “Give me the column/element called ___”

A helpful mental picture from Advanced R (Wickham): if a list is a train, and each element is a train car, then:

  • x[4:6] gives you a smaller train made of cars 4 through 6 (still a train — a list)
  • x[[5]] opens car 5 and hands you what’s inside it (not a train anymore)

This is why [ on a list always returns a list (even a list of length 1), while [[ and $ reach inside and hand you the actual object stored there.

Our parent_info column is a list-column — each element of kids$parent_info is itself a list. It’s a good place to see [ vs [[ vs $ in action.

Activity 2: Selecting Rows and Columns

Data frames behave like a cross between a list (each column is an element) and a matrix (rows and columns). When subsetting with two indices, the pattern is:

data[rows, columns]

  • The first position (before the comma) says which rows
  • The second position (after the comma) says which columns
  • Leaving a position blank means “give me all of them”
# All columns for child 5
kids[5, ]

# The mvpa_min column, for all children
kids[, "mvpa_min"]

Your turn

Simplify vs. preserve: one more thing to notice

Compare these two approaches to grabbing a single column:

kids[, "mvpa_min"] # matrix-style: simplifies
kids["mvpa_min"] # list-style: preserves

They select the same values, but return different types of objects:

class(kids[, "mvpa_min"])
class(kids["mvpa_min"])

kids[, "mvpa_min"] simplifies down to a plain vector, because you asked for it “matrix style” (row, column). kids["mvpa_min"] treats kids like a list and hands you back a smaller data frame with one column, preserving the original structure. This distinction is a common source of bugs — a function that works fine when you select multiple columns can break unexpectedly when only one column is selected, because the object type silently changes. (Tibbles were designed to avoid this: kids[, "mvpa_min"] on a tibble still returns a tibble, not a bare vector — try it and compare to a base data.frame.)

Activity 3: Logical Subsetting

So far we’ve selected rows by their position (row 5, rows 2/5/8/12). But in research data, we usually want to select rows by whether they meet a condition — “give me children who did X” rather than “give me row 7.”

This is where logical subsetting comes in. A logical condition like:

kids$mvpa_min >= 60

produces a vector of TRUE, FALSE, and possibly NA — one value per row. When you put that logical vector inside [, R keeps only the rows where the value is TRUE, and returns NA for rows where the condition itself was NA (this is different from using which(), which silently drops NAs instead — worth knowing when you’re not sure why your row counts don’t match).

Activity 4: Combining Conditions

Multiple logical conditions can be combined with:

Operator Meaning
& AND (both conditions must be TRUE)
| OR (at least one condition must be TRUE)
! NOT (flips TRUE/FALSE)

Always use the vectorized & and | here (not && / ||, which only compare a single value each and are meant for if statements).

kids$mvpa_min >= 60 &
  kids$bmi_z < 1

#

Why the parentheses matter: without them, R would evaluate & before | in a way that changes the meaning of the statement (operator precedence). The parentheses force the OR condition to be evaluated as a single unit before it’s combined with the AND. When in doubt, use parentheses to make your intent explicit — even when they’re not strictly required, they make code easier for you (and others) to read later.

Key Takeaways

  1. What object am I working with? (kids, kids$parent_info, kids$id, …)
  2. What do I want to extract?
    • [ to subset (keeps the same structure/type — a smaller train)
    • [[ to extract a single element, unwrapped (open one car)
    • $ to extract a single named element (shorthand for [[)
  3. Which rows do I want? Position (1:5, c(2, 5, 8)) or a logical condition (kids$mvpa_min >= 60)
  4. Which columns do I want? By name: c("id", "age", "mvpa_min")
